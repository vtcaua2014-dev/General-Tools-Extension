SECURITY

Controlled distribution, not false promises.

Browser extensions are installed on the user's device, so their client-side code can ultimately be inspected. This store focuses on authenticity, integrity, access control, and reducing unnecessary exposure.

Implemented protections

Protected package directory. Extension files are not directly exposed as public static files.

Short-lived download tickets. Downloads require a server-issued HMAC token with an expiration time.

SHA-256 verification. The server computes and returns the expected package hash for integrity verification.

License acknowledgement. A user must explicitly accept the current proprietary license before requesting a package.

Security headers. The server sends CSP, frame protection, MIME-sniffing protection, Referrer-Policy, Permissions-Policy and HSTS when deployed over HTTPS.

No secrets in the frontend. Signing secrets stay in environment variables on the server.

No fake installation. Direct installation is only exposed when supported by Firefox signed-XPI flow or a custom Chromium integration API.

For extension developers

Do not place API keys, private signing keys, server credentials, or security-sensitive business logic in the extension package. Anything delivered to a user's browser should be treated as inspectable.
